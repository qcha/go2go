# Запуск горутин в цикле

## Условие

Что может вывести следующий код? Гарантирует ли программа вывод всех чисел?

```go
package main

import "fmt"

func main() {
    for _, val := range []int{1, 2, 3} {
        go fmt.Println(val)
    }
}
```

Поправьте код так, чтобы программа гарантированно печатала все числа. Порядок вывода не важен.

Вопросы:

* Гарантирует ли код вывод всех чисел?
* Почему?
* Как исправить код?
* Будет ли порядок вывода гарантирован после исправления?

## Решение

Код не гарантирует вывод всех чисел, а результат работы не детерминирован.

Наш `main` запускает несколько горутин и сразу завершается. Когда завершается `main` - завершается и вся программа: она не ждет, пока остальные горутины успеют выполниться.

Поэтому программа может ничего не вывести, может вывести часть чисел, а может успеть вывести все.

Чтобы гаранттировано дождаться завершения всех горутин можно использовать `sync.WaitGroup`:

```go
package main

import (
    "fmt"
    "sync"
)

func main() {
    var wg sync.WaitGroup

    for _, val := range []int{1, 2, 3} {
        wg.Add(1)
        go func(val int) {
            defer wg.Done()

            fmt.Println(val)
        }(val)
    }

    wg.Wait()
}
```

После такого исправления программа гарантированно напечатает все числа, но порядок вывода все равно будет недетерминированным. Например, возможны оба варианта:

```text
1
2
3
```

```text
2
1
3
```

### Проблема с замыканием

В этой задаче нет проблемы захвата переменной цикла: в исходном варианте `go fmt.Println(val)` значение `val` вычисляется при выполнении оператора `go`, а в исправленном варианте `val` явно передается аргументом в анонимную функцию.

Если написать код через замыкание вида `go func() { fmt.Println(val) }()`, то до Go 1.22 была отдельная проблема с захватом переменной цикла. Подробнее про это разбиралось в [похожей задаче](./closure_in_for.md).

## Итого

Главная проблема кода не в цикле, а в том, что `main` завершается раньше запущенных горутин. Для ожидания их завершения нужен механизм синхронизации, например `sync.WaitGroup`.

После исправления все числа будут напечатаны, но порядок вывода не гарантирован.
